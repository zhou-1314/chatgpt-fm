先来说说背景，理解 Jalapeño 之前，我们需要先聊清楚两件事：AI 推理到底是什么，以及为什么大公司都在往自研芯片这条路上走。

所谓 AI 推理，英文叫 inference，指的是你拿一个已经训练好的模型，把它用起来，让它处理你的输入然后生成输出结果。最直观的例子就是你在用 ChatGPT 的时候，你输入一段话，模型一个词一个词地把回答生成出来，这个生成过程就叫推理。和训练不一样，训练是一件费时费力、一次性的事情，而推理是每时每刻都在发生的——现在 ChatGPT 每天服务亿级别的用户，每一次对话都是推理，算力消耗是巨大的。

推理从技术层面来看，分成两个截然不同的阶段，这两个阶段的硬件瓶颈完全不一样，这非常关键。第一个阶段叫 prefill，也就是预填充。这个阶段是系统读取你的整段输入，把它处理完，建立对话的初始上下文。这是个计算密集的过程，就像一个厨师一口气把今天所有食材的备菜工作都做完，需要高强度的计算能力，芯片的浮点运算速度是瓶颈。第二个阶段叫 decode，也就是解码。这个阶段是模型一个 token 一个 token 地把回复生成出来，token 你可以理解成大约四个英文字母或者一两个中文字，每生成一个 token 都需要从内存里读取大量的模型状态。这个阶段的瓶颈不是计算，而是内存带宽——内存读得越快，生成速度越快。把 decode 阶段比作厨师端菜，瓶颈不是厨师有多能干，而是从厨房到餐桌的距离和他每次能端多少菜。

这两个阶段的不同需求，给硬件设计带来了很大的挑战。一块芯片如果在 prefill 阶段很强，不一定在 decode 阶段也很强，反之亦然。传统上，如果你要追求更高的吞吐量，也就是同时服务更多用户，你可能要把很多请求攒在一起批量处理，这会增加单个请求的等待时间；如果你要追求低延迟，也就是让每个用户都能快速得到响应，你可能不得不牺牲一些效率。这个两难困境是 AI 推理领域长期存在的痛点。

英伟达的 GPU 是为训练大模型做了大量优化的通用计算芯片，用来做推理当然也能做，而且目前绝大多数推理基础设施都跑在 GPU 上，但 GPU 没有针对推理这两个阶段做专门的深度协同优化。

这就是为什么我们看到越来越多的大公司开始做自己的推理芯片。谷歌做了 TPU，亚马逊做了 Trainium 和 Inferentia，Meta 做了 MTIA，微软也在悄悄布局。这些公司有一个共同的体会：当你能同时控制芯片、内存、网络、系统软件和应用软件，从头到尾全部自己做，用真实工作负载的经验去改进每一层，你能达到的性能和效率，是买别人现成芯片所做不到的。

最好的类比是苹果的 M 系列芯片。苹果把芯片和操作系统、应用框架都自己做了，能做到极致的协同优化，在性能功耗比上大幅超越了用第三方芯片的竞争对手。OpenAI 现在走的是同一条路，只不过他们优化的对象是大语言模型推理，而不是通用的消费电子应用。

好，背景说清楚了，我们现在进入文章的核心内容，按几个关键维度来拆解。

第一个维度：Jalapeño 到底是一块什么样的芯片，基本情况是怎样的。

Jalapeño 是 OpenAI 的第一块自研推理芯片。名字取自墨西哥辣椒，那种绿色的、很辣的小辣椒，英文大概发音是"哈拉嗯纽"。用辣椒命名芯片，在硅谷其实有一个隐约的传统，给人感觉是快、热、带劲。

这块芯片的额定功耗是七百瓦，但文章里特别提到，在实际测试的工作负载上，持续功耗保持在五百五十瓦或者更低。这个区别值得关注。额定功耗是理论上的峰值，而实际功耗才是数据中心运营时真实消耗的电力。能在比额定功耗低将近百分之二十五的实际功耗下跑出这样的成绩，说明能效设计做得相当扎实。数据中心的用电成本是一笔巨大的开支，功耗越高，散热系统越复杂，机柜设计要求也越高，每降低一点功耗在大规模部署时都是真金白银的节省。

文章还强调，Jalapeño 是一个多代平台的起点。第一代是现在正在准备部署的，第二代已经在深度开发中，第三代也在规划成形。这说明 OpenAI 对自研芯片这条路有明确的长期承诺，不是试试水就算了。

第二个维度：测试数据说明了什么，我们来仔细看这些数字。

OpenAI 使用了 InferenceX 这个公开基准测试来评估 Jalapeño 的性能。InferenceX 是由 SemiAnalysis 发布的，SemiAnalysis 是半导体和 AI 基础设施领域的知名研究机构。这个基准测试衡量的是完整的 AI 请求处理流程，也就是从用户发出请求到系统返回完整响应的全链路性能，而不是只看芯片某个孤立的单点指标。

OpenAI 在三个公开大模型上跑了测试，分别是 GPT-OSS 一百二十 B、DeepSeek R 一六百七十 B 和 Kimi K 二点五一万亿参数。这里 B 是 billion 十亿的意思，所以一百二十 B 就是一千二百亿参数；一万亿参数通常用 T 表示，Kimi K 二点五是目前公开的最大模型之一。这三个模型来自不同的机构，GPT-OSS 是 OpenAI 开源的，DeepSeek R 一是深度求索做的，Kimi K 二点五是月之暗面做的。OpenAI 有意选了来自不同机构的模型，是为了证明 Jalapeño 的架构不是只对自家模型友好，对外部机构的模型同样有效。

在看具体数字之前，我先解释几个测试指标的含义，这样数字才有意义。

第一个指标是峰值混合每千瓦 token 数，也就是在满足用户延迟要求的前提下，每消耗一千瓦电力，系统每秒能处理多少 token。这是衡量能效的核心指标，数字越大越好。

第二个指标是端到端延迟，从用户发出请求到收到完整响应的总时间，越低越好。对于 agent 这样需要连续多步调用的场景，端到端延迟的重要性尤为突出，因为每一步的延迟会叠加。

第三个指标是最小 token 生成间隔，英文缩写是 TBT，也就是 Time Between Tokens，相邻两个 token 之间的生成时间间隔。这影响的是用户感受到的文字流速，是一个字一个字快速蹦出来，还是要等很久才出现下一个字。TBT 越低，用户感受到的响应越流畅。

现在来看 GPT-OSS 一百二十 B 的结果。峰值每千瓦吞吐量，Jalapeño 是八万五千四百四十八个混合 token，对比系统是四万四千九百六十个，大约高了一点九倍。端到端延迟，Jalapeño 是一点零三秒，对比系统是一点八秒，低了一点七倍。最小 token 生成间隔，Jalapeño 是零点六九毫秒，对比系统是一点八七毫秒，低了约二点七倍，换算成每秒每用户的 token 生成速率，Jalapeño 是每秒一千四百五十九个，对比系统是每秒五百三十五个。还有一个更夸张的维度：在对比系统的 token 生成速率下，Jalapeño 的每千瓦吞吐量是对比系统的约五十三点七倍。这个数字的含义是：当你把响应速度固定在一个特定水平，Jalapeño 能在同样功耗下服务多五十多倍数量的并发请求。

再看 DeepSeek R 一六百七十 B 的结果。这个模型不只参数更多，它还是混合专家架构，也就是 Mixture of Experts，简称 MoE。MoE 的意思是模型内部有很多个专家子网络，每次推理只激活其中的一部分，实际计算量比参数量暗示的要小，但内存需求很大，而且负载均衡很复杂。Jalapeño 在这个模型上，峰值每千瓦吞吐量高了一点七倍，端到端延迟低了三点六倍，最小 token 生成间隔低了四点一倍。在特定条件下的每千瓦吞吐量比较，高了大约一百零四倍。

最后看 Kimi K 二点五一万亿参数的结果，这是三个测试模型里最大的。Jalapeño 峰值每千瓦吞吐量高了一点五倍，端到端延迟低了三点四倍，最小 token 生成间隔低了三点八倍，在特定条件下的每千瓦吞吐量高了约五十六倍。

把这些数字放在一起看，有一个很清晰的模式：模型越大，Jalapeño 在延迟方面的优势越明显。一百二十 B 的模型延迟降低了一点七倍，而六百七十 B 和一万亿参数的模型延迟降低了三点四到三点六倍。这和文章里说的一个结论吻合：在内部测试里，Jalapeño 对 OpenAI 前沿模型的优势比在开源模型上更大，工作负载越大越复杂，架构优势就越突出。

文章里用了一个概念叫帕累托前沿，也就是 Pareto frontier。在同时优化两个互相冲突的目标时，帕累托前沿上的解意味着你没有办法在不牺牲其中一个目标的前提下继续改善另一个——这是最优解的边界。文章说 Jalapeño 在吞吐量效率和延迟这两个维度上都达到了帕累托前沿，也就是说它不是用效率换了速度，也不是用速度换了效率，而是两个方向同时做到了最优。这才是这个结果最重要的意义。现有的硬件系统通常要在吞吐量和延迟之间做权衡，而 Jalapeño 号称打破了这个权衡。

第三个维度：Jalapeño 的架构是怎么设计的，为什么能同时做到高效率和低延迟？

文章里有一段话我觉得最值得记住，大意是：Jalapeño 的设计从一个问题出发——如果一块芯片的主要任务就是服务现代和未来的语言模型，尤其是交互式 agent，那我们应该怎么设计它？

这个问题看起来很朴素，但背后的含义很深。它意味着 Jalapeño 不是一块通用芯片，它就是为大语言模型推理量身定制的，所有的设计决策都围绕这个目标来做，不为其他用途留妥协空间。

架构上有几个关键的设计思路。

第一是最小化数据搬运。在多芯片系统里，数据在不同芯片之间的传输是延迟的重要来源。如果一个处理器在等另一块芯片的数据，它就在空转，这是巨大的浪费。Jalapeño 的设计让模型状态，包括 KV cache，也就是 Key-Value cache，能被显式地放置在本地。

我解释一下 KV cache 是什么。在大语言模型生成回复的过程中，每生成一个新的 token，模型都需要参考它之前处理过的所有内容的摘要信息——这些摘要就存储在 KV cache 里。你可以把它想象成一个服务员的记事本，他需要记住这桌客人今天点了什么、说了什么，才能在整个用餐过程中保持连贯性。对话越长，KV cache 越大；KV cache 越大，每生成一个 token 需要读取的内存数据就越多。如果这个记事本在需要的时候就在手边，随时能翻看，效率就很高；如果每次翻看都要从另一个地方搬过来，就会造成大量的等待时间。Jalapeño 的设计让这个"记事本"就在本地，在推理的不同阶段，系统能激活合适的计算、内存和网络资源组合，而不需要大量的数据搬运。

第二是把网络集成进架构里。文章说 Jalapeño 的网络是架构不可分割的一部分，而不是一个附加的组件。它的大规模网络域让整个推理工作负载可以在一个互联的系统里运行，最小化需要跨越系统边界的数据移动。这对大模型尤其重要，因为超大规模的模型必须分布在多块芯片上，芯片之间的通信延迟直接影响推理速度。如果网络是芯片原生支持的，通信效率就会比后来加上去的外部互联方案高很多。

第三是平衡性和可替换性。文章说 Jalapeño 是一个"平衡且可替换"的加速器，能同时在 prefill 和 decode 两个阶段都表现出色，而且能适应不同模型架构之间这两个阶段比例的变化。这对 agent 场景格外重要。agent 在处理任务时，工作负载的特征变化很大——有时候是短 prompt 长输出，有时候是长 prompt 短输出，有时候是非常多的短步骤连续调用，芯片需要能灵活应对这种变化，而不是只擅长某一种固定模式。

第四个维度：AI 参与了芯片的开发——这个角度最值得深思。

这是整篇文章里我觉得最有前瞻性的部分，也是很多人可能快速扫过去但其实非常值得细读的地方。

文章说，整个团队从最初设计到 tapeout——也就是芯片设计定稿、送去制造，这个过程行业里叫做流片——只用了九个月。九个月！芯片行业的工程师看到这个数字可能下巴都要掉了。传统的芯片设计周期通常是两到三年，甚至更长，涉及大量的手工设计、仿真验证、物理实现等工作，每一个环节都可能出问题需要返工。

当然，九个月这个数字的背后一定有很多前提条件，比如这可能是在很多已有基础之上做的，团队规模也可能很大。但即便如此，AI 工具在这个过程中的贡献是真实的。文章说 AI 帮助团队探索了大量的设计方案，缩短了设计、测量和验证的循环周期，并且持续针对真实的模型工作负载做迭代优化。AI 还帮助优化了芯片的算术电路，让团队在预定时间内，在有限的芯片面积上放入了更多的计算能力。

在软件层面，AI 的应用更加具体。文章说 Jalapeño 被刻意设计成一个对人类和 AI 都清晰可预测的编程目标。工程师可以用本地张量、显式通信和可预测的同步原语来描述计算任务，然后 AI 工具可以优化这些任务如何在系统里进行映射、放置、调度和协调。文章里的原话大意是，这种清晰可预测的结构给了 AI 一个可处理的方式来解决并行编程这个传统上极其困难的问题。并行编程，也就是如何让多个处理器同时高效地工作而不互相干扰，一直是计算机科学里的经典难题之一，即使是经验丰富的人类工程师也经常搞出各种奇怪的 bug。而当芯片的编程接口被设计得足够清晰和可预测，AI 就能更有效地在这个框架里做优化，因为搜索空间被大大缩小了。

最具体的例子是使用 Codex 配合 GPT-Astra——Codex 是 OpenAI 的代码生成模型，GPT-Astra 你可以理解成 OpenAI 当时的前沿模型——团队在两个月内把三个最初不在 Jalapeño 生产计划里的开源模型，也就是 GPT-OSS 一百二十 B、DeepSeek R 一和 Kimi K 二点五，全部带到了高性能水平。两个月完成三个量级不同的大模型在全新芯片架构上的适配和内核优化，这个速度是相当惊人的。

更具体的性能数字是：在 GPT-OSS 的注意力机制模块和混合专家模块这些特定代码块上，AI 生成的内核实现比此前人类专家手写的实现快了一点五到一点八倍。我需要强调一下这个数字的边界，文章明确说，这个倍数是针对特定选取的代码块，不是整个模型的整体性能提升。整个模型涉及很多其他的计算部分，所以不能直接把这个数字说成"AI 让整个模型快了一点八倍"。但即便如此，这也是一个非常有说服力的数据点，证明了 AI 辅助编程在底层系统软件、甚至硬件内核这个领域，已经能够产生可测量的实质性性能提升，而不只是写写上层的业务逻辑代码。

第五个维度：这对行业格局意味着什么？

OpenAI 在文章里提到了一个"全栈优势"的概念。他们的意思是，当你能够自己设计模型、产品、服务软件、芯片、内存、网络和整个系统，用从真实工作负载里学到的东西来改进每一层，你能达到的是别人做不到的。这种全栈控制力，让优化可以跨越不同层级的边界——芯片知道模型的结构，模型知道芯片的特性，服务软件知道两者的行为，整个系统可以做整体的协同优化，而不是每一层各自优化之后拼在一起。

文章里列举了 Jalapeño 扩展了哪些可能性：超快模式的推理现在能达到之前只有快速模式才有的效率；快速模式的推理能达到之前只有批量处理才有的效率；批量处理的效率也进一步提升了。简单说就是，整个效率曲线往上移了一个档，用户能在不同的响应速度档位里享受到比以前更低的成本。

部署时间表方面，文章说计划在今年年底之前开始在 OpenAI 自己的计算基础设施里部署 Jalapeño。与此同时，OpenAI 明确表示会继续广泛使用英伟达等合作伙伴的加速器，用于训练和推理工作负载。自研芯片和第三方芯片是并行策略，不是替代关系。这个表态一方面是为了安抚合作伙伴关系，另一方面也是现实的——英伟达的训练芯片仍然是现阶段最重要的算力来源，短期内没有什么能替代。

好，说完了文章的核心内容，我们来聊聊这对我们做 AI 产品和工程的人，有什么具体的实践意义。

第一件事是关于 agent 场景的机会窗口。文章里反复出现的一个词就是 agent，也就是 AI 智能体。为什么 agent 特别在乎延迟？因为 agent 完成一个任务需要连续调用模型多次，每一步的结果成为下一步的输入，延迟是叠加的。举个具体例子：如果你的 agent 需要做五十步推理，每步端到端延迟是两秒，那整个任务要一百秒，大多数用户根本等不了。但如果你把每步延迟从两秒降到零点五秒，同样的任务只要二十五秒，用户体验天壤之别，很多之前只能做离线任务的工作流就可以做成实时交互了。Jalapeño 把端到端延迟降低了三到四倍，直接扩大了 agent 场景的可行空间。如果你现在在做多步推理的 agent 产品，等 Jalapeño 开始规模部署之后，你应该回过头来重新评估一些之前因为延迟太高而放弃的设计——以前做不了的事情，很快可能就能做了。

第二件事是关于成本预期的管理。更高效的推理意味着同样的电力和硬件能完成更多有用的工作。从长期看，这会压低推理成本，有可能反映到 API 定价上。当然这个过程不会是立即发生的，OpenAI 不一定会马上降价，他们也可能把效率提升转化为利润，或者再投入到模型研发和基础设施里。但从趋势上看，推理成本的持续下降是大概率事件，而 Jalapeño 是这个趋势的一个加速器。对于那些现在因为 API 成本太高而无法规模化使用大模型的产品，这个趋势是值得持续跟踪的。

第三件事是对在大公司或者 AI 基础设施方向工作的工程师的一个信号。这篇文章明确证明了一件事：全栈垂直整合这条路是对的，而且回报是真实可测量的。如果你的公司有规模做这件事，或者你在参与 AI 基础设施的长期布局，这个方向是值得投入的。这条路很难，需要极强的跨层工程能力，芯片、系统软件、模型、应用这几层你都得有人能做，但一旦做成，护城河是很深的。

第四件事是对独立开发者和小团队的说明。目前 Jalapeño 还没有开放给外部商用，它是 OpenAI 自己用的基础设施。所以短期内你没有办法直接选择在哪块芯片上跑你的模型。你能做的是通过 OpenAI API 使用他们的服务，等 Jalapeño 规模部署之后，你自动就是受益者，响应速度和潜在成本都可能改善，而你自己不需要做任何改变。与此同时，你也可以开始关注 InferenceX 这个基准测试，了解它的评测方法论，如果你以后需要评估不同 AI 推理硬件的采购决策，这是一个不错的参考框架。

第五件事，我想专门说一下 AI 辅助硬件设计这个角度的长期意义。今天，AI 帮助优化了 Jalapeño 的部分内核代码，让特定模块比人类专家代码快了一点五到一点八倍；今天，AI 工具让芯片的设计周期从传统的多年缩短到九个月。你往前推十年，这两件事都是不可想象的。而今天这只是起点。如果 AI 辅助硬件设计的能力继续以现在的速度进化，那么未来五年、十年，我们看到的芯片设计速度和优化深度，会是今天完全无法预测的。而且这不只是 AI 推理芯片这一个领域的事——材料科学、制药研发、航空工程，所有需要在复杂约束下做大规模设计探索的领域，都会受到这种能力的影响。AI 用来加速自己所依赖的基础设施的设计，这个循环飞轮一旦转起来，我们就进入了一个完全不同的加速阶段。

最后，我从个人角度做一个总结和点评。

Jalapeño 这篇文章，表面上是一个芯片发布公告，但往深里看，它标志着至少三件重要的事情同时发生。

第一，OpenAI 正式成为了一家全栈 AI 公司，不再只是模型公司。从今以后，他们在芯片层面有了自己的控制权。这在成本、速度和差异化方面都会带来长期的结构性优势。竞争对手想要在模型之外也追上 OpenAI，需要跨越的门槛又高了很多。

第二，AI 辅助硬件设计已经不是概念，而是已经产出了可测量的成果。从设计到流片九个月，AI 生成代码在特定模块上超越人类专家——这两件事放在一起，预示着一个新的开发模式正在成形。这个模式的影响范围，我认为远不止于 AI 芯片领域。

第三，我个人认为，我们应该带着一定的审慎去读这篇文章。文章里有一些细节是没有完全披露的，比如对比系统具体是什么配置，是英伟达哪一代 GPU，用了多少张卡，系统软件是什么版本；InferenceX 基准测试能不能完全代表所有真实生产场景；一点九倍效率提升和三点六倍延迟降低在实际多样化工作负载下是否能复现。这是 OpenAI 自己发布的测试结果，不是第三方独立评测，我们应该带着这个意识去读，等待第三方机构的独立验证。但即便有这样的保留，如果数字的量级是真实的，那 Jalapeño 的表现就是相当显著的进步。

总的来说，这是 OpenAI 在 AI 基础设施层面一个重要的里程碑。自研芯片这件事不是所有公司都能做到的，需要钱、人才、时间和真实的大规模工作负载作为优化目标，OpenAI 这些条件都有。对于我们这些在 AI 浪潮里做产品和工程的人，理解这个趋势，把它纳入自己对未来一两年行业走向的判断，是很有必要的。高效率的推理意味着更低的成本，更低的成本意味着更广泛的应用，更广泛的应用意味着更多的数据和经验，这个循环会继续加速。
