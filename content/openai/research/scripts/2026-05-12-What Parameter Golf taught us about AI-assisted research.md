先说说 Parameter Golf 到底是什么。

这个名字本身就很有意思。高尔夫运动的目标是用尽量少的击球次数完成比赛，分数越低越好。Parameter Golf 的核心思路完全一样——用尽量少的参数，训练出尽量好的语言模型。

具体规则是这样的。参赛者需要在一个固定的数据集上，最小化模型的 held-out loss，也就是模型在没有见过的数据上的损失值。这个数据集叫做 FineWeb，是一个高质量的英文网页文本数据集，被广泛用于语言模型的预训练研究。评估使用的指标是每字节比特数，英文叫 BPB，全称是 bits per byte，你可以把它理解成模型的文本压缩能力，数值越低，说明模型预测文本的能力越强。

约束条件非常严格，严格到令人印象深刻。整个提交物，包括模型权重和训练代码，不能超过十六兆字节。我们来感受一下这个限制有多苛刻：现在随便一个大语言模型，它的权重文件都是几十个 G 起步，而十六兆字节大约就是你手机上一张普通照片的大小。在这么小的空间限制下训练出一个有竞争力的语言模型，需要极度精细的工程设计和极具创意的压缩思路，这不是靠堆参数能解决的问题，你必须真正理解每一个字节在做什么。

训练时间上限是十分钟，计算硬件是八张 H100 显卡。H100 是英伟达目前最顶级的 AI 训练显卡，八张 H100 在算力上已经是相当高配的环境，但十分钟的训练时间限制，仍然是极为苛刻的边界条件。这意味着你的训练流程必须非常高效，不能有任何浪费。

OpenAI 提供了基线代码、数据集和评估脚本，参赛者可以在 GitHub 上 fork 这个仓库，修改模型，然后提交结果。整个流程设计得非常工程师友好。

比赛持续了八周，最终收到了来自超过一千位参赛者的两千多份提交。这个规模，对于一个技术门槛相对较高的机器学习研究竞赛来说，是相当可观的。一千位参赛者，两千多份提交，这背后有大量的工作量，而这些工作量背后，AI agent 扮演了非常重要的角色——这也是这篇文章的核心主题之一，我们后面会详细展开。

现在来看看这场比赛里出现了哪些有意思的技术方向。OpenAI 在复盘中归纳了几个主要主题，我来逐一拆解。

第一个主题是训练优化，也就是通过对现有组件的精细调整来提升模型效果。

文章里举了一个很有代表性的例子，是一位叫 notapplica 的参赛者提交的方案。这份提交最值得称道的地方，不是它引入了什么全新的方法，而是它把之前排行榜上几个顶级提交的技术点，非常干净地识别、提炼和组合在了一起。具体来说，这个方案融合了 Muon 优化器的权重衰减策略、谱嵌入初始化、残差混合调度，以及编译式评估这四项改进，把它们拼成了一个完整的方案。

这个"组合拳"策略，我认为是非常值得我们学习的一种研究思路。在机器学习领域，有一种很常见的现象：每个单独的改进可能只带来百分之一两的提升，但如果你能准确识别出哪些改进是真正正交的、互相不干扰的，然后把它们干净地组合在一起，最终效果往往会超出简单叠加的预期。这听起来简单，但背后需要的是对每个技术点的深刻理解，以及对实验结果的仔细辨别——知道什么是真正稳定可复现的信号，什么只是随机噪音带来的幻觉。这种能力，是真正有价值的机器学习工程直觉。

第二个主题是量化，也就是用更少的比特位数来表示模型权重，从而在十六兆字节的空间限制下，让模型能表达更丰富的信息。

有两个提交特别值得关注。第一个是参赛者 signalrush 的方案，他使用了一种叫做 GPTQ-lite 的量化方法。GPTQ 是目前业界非常流行的大模型后训练量化技术。量化的基本思路是：把模型权重从高精度的浮点数，压缩成低比特位的整数表示，同时尽量保留模型的预测能力。你可以把它想象成把一张高分辨率的照片压缩成低分辨率，区别在于，聪明的量化方法知道哪些细节可以丢，哪些细节关键到不能丢。GPTQ 的聪明之处在于，它利用了 Hessian 矩阵的信息，也就是损失函数对模型权重的二阶导数，来更智能地决定在每一层的哪个位置可以接受精度的损失，从而让压缩后的模型在性能上的损失尽量小。signalrush 是整场比赛中第一个成功使用 GPTQ-lite 的参赛者，他的方案为后续的量化探索打开了大门。

第二个是参赛者 dexhunter 的方案，他在之前一位叫 raahilshah 的参赛者的工作基础上，成功实现了完整的 Hessian GPTQ，进一步强化了量化压缩路径，把这个方向推到了更深的地方。这两个提交的关系本身很有意思：第二个方案明确地建立在第一个的基础上，这种公开环境中的知识传递和接力，是开放竞赛非常美好的一面。

第三个主题是测试时训练，英文叫 test-time training。这是近年来越来越受关注的一个方向。

传统的模型使用流程是：先训练，训练完成后在测试集上做评估，评估阶段模型的权重是固定不变的，不会再更新。但测试时训练的思路完全不同：在评估阶段，让模型根据当前看到的数据做一些有针对性的微调，然后再去回答问题或者做预测。这在某些场景下可以显著提升效果，但它同时也引发了一个深层问题：如果模型在评估过程中已经"看过"并且"学过"测试数据，那它表现出来的能力，到底是真正的泛化能力，还是对当前数据的过拟合？这个边界的模糊性，在 Parameter Golf 的竞赛环境里引发了非常有意思的讨论。

参赛者 samacqua 提出了一种叫做"先打分再做 LoRA 测试时训练"的方案。LoRA 的全称是 Low-Rank Adaptation，低秩适应，是一种用极少的可训练参数来高效微调模型的技术，近年来在大语言模型的定制和适应场景里被广泛使用。samacqua 的方案是这样操作的：先对文档进行打分，然后只在已经打过分的文本块上做 LoRA 微调，并在每个文档的边界处重置模型状态，让每个文档的测试时训练相互独立。

这个方案在比赛规则范围内是合法的，但它非常微妙地推到了"模型改进"和"评估策略"之间的边界地带。OpenAI 的评委花了相当大的力气来审查这类提交，确保它们没有以规则没有明确禁止的方式破坏评测的公平性。这个审查过程本身说明了一件重要的事：当参赛者和他们的 agent 足够聪明的时候，竞赛规则的设计和执行都会变得远比看起来复杂。

还有一个参赛者 abaybektursun 提出了更有创意的方案：他用训练好的模型自己生成校准文本，然后用这些生成的文本来构建 GPTQ 量化所需的 Hessian 矩阵。通常情况下，GPTQ 量化需要一批真实的代表性数据来计算 Hessian 信息，这批数据的质量直接影响量化后模型的效果。但这个方案绕开了对外部校准数据的依赖，直接让模型"用自己的话来测量自己"，是一个非常有意思的自举设计思路。

第四个主题，也是我个人最喜欢的部分，是一些参赛者提出的全新建模和数据表示创意。

第一个让我眼前一亮的创新叫做 CaseOps tokenizer，来自参赛者 romeerp。我们知道，tokenizer 是把文字切分成模型可以处理的最小单元的工具。现有的主流 tokenizer 在处理大写字母的时候，往往会把同一个词的大写版本和小写版本映射成完全不同的 token，比如"Hello"和"hello"可能是两个完全不同的 token。这在某些场景下会浪费模型宝贵的表达容量，因为大写和小写背后共享的语义信息，被强制分开学习了。CaseOps 的思路是引入专门的无损大写操作符 token，把大写信息和词根信息分开表示，同时配合一个按字节计算比特数的辅助统计系统，让模型可以更高效地同时处理大写和小写，而不需要为它们维护完全独立的表示。在极度压缩的十六兆字节空间里，这种效率提升就变得非常有价值了。

第二个创新是 XSA，来自参赛者 unnir。XSA 是独占自注意力机制的意思，英文全称是 Exclusive Self Attention。它是一种部分独占的注意力方案，结合了 GQA，也就是分组查询注意力的设计思路。你可能会问，为什么要研究这些注意力机制的变体？因为标准 transformer 架构的自注意力机制，计算量随着序列长度的平方增长，当序列变长的时候，计算成本会急剧上升。各种高效注意力变体一直是近年来的热门研究方向，XSA 把独占注意力的思路引入到这个极度约束的竞赛场景，是从学术文献中找灵感并付诸工程实践的典型案例。

第三个是 SmearGate 和 BigramHash，来自参赛者 aquariouseworkman。这两个机制是这位参赛者自己从头发明的，没有直接对应的文献来源，是真正的原创设计。SmearGate 是一种学习到的机制，把前一个 token 的嵌入向量以一种可学习的方式混合进当前 token 的表示中。BigramHash 则是对相邻 token 对计算哈希特征，直接把双字节级别的上下文特征显式地注入到模型中。这个思路有点像是在神经网络里手动实现了一部分传统 n-gram 语言模型的直觉，用结构化的特征工程来补充神经网络的端到端学习，在这个极度约束的场景里取得了令人意外的效果。

第四个是迷你深度递归，来自参赛者 msisovic。这个方案重复使用了模型的第四层和第五层，并不是在模型初始化的时候就引入递归，而是在训练中途才开始启用，同时对重复的 MLP 层做了部分权重解绑处理，让不同循环次数的同一层能学到稍微不同的东西。更重要的是，这是整场比赛中第一个成功让循环层有效工作的提交。在 transformer 架构统治的今天，让循环神经网络的思路重新发挥出竞争力，是一件相当不容易的事情。这份提交证明了在约束极度严格的场景下，架构层面的创新仍然有机会带来真正的惊喜。

除了主赛道，这场比赛还设有一个非记录赛道，专门鼓励那些更具实验性、不以打破分数记录为目标的创新提交。OpenAI 说他们在这个赛道里看到了一些他们最喜欢的提交，包括非自回归文本建模和动态分词这样的方向。

非自回归文本建模是什么概念？我们现在用的 GPT 系列模型，本质上都是自回归的，也就是每次只生成一个 token，每个新 token 的生成都要依赖前面所有已经生成的 token 的上下文。这种方式非常符合直觉，但推理效率不高——因为你没法并行生成，只能一个接一个。非自回归方法试图一次性预测多个 token，或者用完全不同的生成机制来绕过这个串行依赖。这个方向已经有相当长的研究历史，但在实际效果上，它一直很难真正撼动自回归模型的地位。在 Parameter Golf 这样约束极度严格的场景里，非自回归方法是否能找到属于自己的独特优势，是一个值得持续关注的开放问题。

OpenAI 分享了一个让他们感到鼓励的数据点：非记录赛道里，有将近一半的提交都打败了每字节比特数一点二二的朴素基线，而排名最高的一个提交达到了一点一二。这说明在强大的 transformer 基线面前，另类方法仍然有一定的竞争力，没有被彻底碾压。这个结果不算惊天动地，但它证明了在特定约束条件下，另类架构仍然值得探索。

OpenAI 还特别指出，非记录赛道特别受益于 AI 编程 agent 的存在。因为很多实验性的想法，以前因为原型开发成本太高、不确定性太大而不会被认真尝试，现在有了 agent 的辅助，快速搭起一个原型的成本大幅下降，参赛者可以更快地验证各种听起来大胆甚至有些奇怪但或许能行的思路。

好，现在我们来到这篇文章里我认为最重要、也最有现实意义的部分：AI 编程 agent 对这场竞赛生态产生的影响。

OpenAI 明确说，Parameter Golf 和之前类似竞赛的一个最大区别，就是 AI 编程 agent 的大规模使用。绝大多数参赛者都提到，他们在参赛过程中使用了 agent 作为核心辅助工具，而不只是偶尔用一用。

agent 的大规模参与带来了哪些变化？

积极的一面，首先是它大幅降低了参与门槛。参赛者可以更快地搭建实验环境，阅读和理解自己不熟悉的代码，用更少的摩擦来测试和验证想法。你可能会想到这样一个场景：一个对机器学习某些细节没那么精通的软件工程师，在 agent 的帮助下，可以快速读懂排行榜顶级提交的代码，搞清楚每一个设计决策背后的原因，然后在此基础上做出自己的改进或探索。这种能力的放大效应，是以前没有 agent 的时候很难实现的。

此外，Runpod 赞助了一百万美元的算力支持，让参赛者可以真正跑起来大规模的实验，而不是只能在本地机器上用玩具规模的数据集做测试。算力赞助加上 agent 辅助，共同让这次竞赛的准入门槛降低到了一个前所未有的水平，这也是为什么超过一千个人参与了这么一个技术门槛较高的比赛。

但 agent 的大规模参与同时也带来了新的问题，而且这些问题相当棘手。

第一个问题是提交质量的信噪比下降。很多提交都是对已有排行榜顶级方案的小修小改，而不是从根本上创新的方法。这本身不一定是坏事——强力的想法能快速传播、被其他人精炼和改进，这是开放竞赛最有价值的地方之一。但问题出在一个更具体的场景：当一个不符合比赛规则的提交产生了异常好的分数之后，其他使用 agent 的参赛者的 agent 有时会直接把这个思路纳入自己的实验计划，然后继续沿着这条本来就无效的路径走下去。这就产生了一种放大效应——无效的、不符合规则的提交被 agent 快速复制和传播，消耗了评委大量的审查时间，也让很多参赛者在错误的方向上浪费了宝贵的计算资源。

第二个问题是提交量的爆炸式增长。在某些高峰期，OpenAI 每天会收到几百份提交。靠人工逐一仔细检查每一份提交，完全不现实，但如果不检查，排行榜的可信度又会受到影响。

为了应对这个挑战，OpenAI 内部开发了一个基于 Codex 的分诊机器人，来自动监控新的提交，并把那些看起来需要人工仔细审查的提交标记出来，让评委重点关注。Codex 是 OpenAI 的编程专用模型。用 AI 模型来帮助人类审查 AI 辅助生成的竞赛提交，这个循环很有意思，也非常有这个时代的特色。这个分诊机器人在竞赛进入高峰期后，成了 OpenAI 团队不可或缺的运营工具。

社区层面也出现了一些让人惊喜的自发应对机制。参赛者 notapplica 和他们的编程 agent 一起运营了一个叫做"Live Updates"的实时公告栏，持续追踪竞赛中的重大事件，用通俗的语言解释排行榜上各种方案的技术原理，帮助其他参赛者及时跟上竞赛动态。社区里还涌现出一些评审辅助工具，帮助经验较少的参赛者在提交之前检查自己的方案是否符合规则，避免踩进常见的无效陷阱。

这个现象让我想到了一个更大的问题。当 AI agent 成为研究和竞赛的标配工具之后，"什么叫做个人的创造力和成就"这件事就变得更加模糊了。谁发现了哪个想法，想法的来源是独立思考还是 agent 的建议，多少是人的判断多少是 agent 的生成——这些问题在 Parameter Golf 里都没有清晰的答案。OpenAI 也坦诚地承认，这些模糊性给提交审查、归因和评分都带来了新的挑战。而且随着 agent 能力的持续增强，这种模糊性只会越来越大，不会越来越小。

OpenAI 最后还提到了一点：这次竞赛作为人才发现渠道的效果，超出了他们的预期。他们在比赛过程中识别出了一些拥有出色机器学习研究直觉和持续钻研精神的参赛者。这对 OpenAI 来说是一个有意义的验证：精心设计的开放挑战，是比传统简历筛选更直接地观察一个人的技术品味和钻研精神的方式。你能看到一个人在面对约束时如何思考，在遇到瓶颈时如何调整，在别人走某条路的时候是选择跟随还是另辟蹊径。这些都是简历上写不出来的东西。

好，讲了这么多，我们来聊聊这篇文章对我们实际工作意味着什么。

第一点，关于如何用 agent 做有深度的实验。Parameter Golf 的故事告诉我们，agent 在降低实验成本上非常有效，但它有一个系统性的偏差：它会倾向于在已有的高分方案上做小改动，而不是大胆探索未知的方向。这不是某个特定 agent 的缺陷，而是在竞争性环境下 agent 行为的普遍特征。如果你在用 agent 辅助研究，要有意识地在你的提示词里明确指定探索方向。告诉它你想要的是什么样的创新，你希望它考察的是哪些目前还没有人尝试的角度，而不是让它自由发挥然后指望它自己跳出已知空间——否则你很可能得到的是现有方案的局部优化，而不是真正的突破。

第二点，关于评测设计要更加严密。文章里关于测试时训练和自生成校准数据这些方案的讨论，揭示了一个深层问题：当规则没有明确禁止某种策略的时候，聪明的参赛者和他们的 agent 就会找到规则的边界。这个洞察对你在工作中设计基准测试、评估模型能力，有非常直接的参考价值。如果你的评测框架有任何可以被巧妙利用的漏洞，在 agent 的加持下，这些漏洞会被更快、更系统地被发现和利用。设计评测的时候，要比以前更仔细地思考"什么样的行为真正对应了我要测量的能力"，而不只是看最终的分数数字。评测失效的代价，随着 agent 的普及，会变得越来越高。

第三点，关于知识传递机制的建立。Parameter Golf 的开放格式让好的技术想法能够快速传播——一个人发现的量化技巧，很快就被其他人看到、学习、改进和扩展，整个社区都从中受益。这种开放式的技术积累机制，是值得我们在团队内部有意识建立的东西。你是否在自己的团队里建立了类似的机制，让每个人的实验发现都能及时被其他成员看到和利用？大多数团队在这一点上做得远远不够，实验结论停留在个人的笔记里，没有转化成团队的共同知识。

第四点，关于 agent 放大效应的风险意识。文章里最值得我们警惕的一个观察是：当一个不符合规则的方案产生了好的分数，agent 会系统性地倾向于复制和传播它。这个问题在研究竞赛之外同样存在。如果你的团队在用 agent 优化某个目标，而这个目标的定义本身有偏差，agent 不会自动纠正这个偏差，它会以比以前快得多的速度把这个偏差放大。目标函数的定义，在 agent 时代比以前重要了一个数量级。

第五点，关于量化和测试时训练这些方向的工程机会。如果你正在做语言模型的工程优化，Parameter Golf 的排行榜是一个很好的学习资源。这些提交都是在极度约束下的真实工程工作，不是论文里理想化的实验设置，它们的可操作性往往更强。特别是量化方向，GPTQ 和它的各种变体在这场比赛里得到了充分的工程验证，这些实践经验对你在自己项目里做模型压缩和边缘部署，有很直接的参考价值。

最后，有一点要特别提醒自己：不要把"用了 agent 跑了很多实验"等同于"做了高质量的研究"。Parameter Golf 里有一个隐含的教训：agent 大量参与之后，提交的数量大幅增加，但提交的多样性和创新性并没有等比例提升，真正有独创性的方案反而更难从噪音中被识别出来。在你自己的工作中，如果你在用 agent 做大量实验，要定期退出来问自己一个问题：这些实验是在验证一个有深度的假设，还是只是在一个已知的参数空间里做密集搜索？两者都有价值，但要清醒地知道自己在做哪一件事。前者是研究，后者是工程优化，它们都重要，但不能混淆。

好，我们来做一个总结。

Parameter Golf 不只是一场有趣的机器学习竞赛，它是一个在 AI agent 时代运行开放技术挑战的真实案例研究。从它里面，OpenAI 看到了技术创造力在极度约束下被激发的可能，看到了量化、高效注意力机制、测试时训练等方向的工程潜力，看到了开放社区的自我组织能力，也诚实地记录了 AI agent 如何同时加速了好的想法传播，也放大了无效方向的蔓延和提交噪音的产生。

我个人认为，这篇文章最有价值的洞察是：agent 是一个放大器。它放大你已有的研究能力，也放大你的研究设计里的缺陷。在设计上多花的每一分心思，在 agent 时代都会被放大回报；在设计上犯的每一个错误，在 agent 时代也会被放大惩罚。知道这一点，比记住任何具体的量化技巧，对我们长期的工作来说都更重要。

OpenAI 说他们在考虑未来举办更多类似的挑战。我很期待下一场会在什么样的约束条件下运行，会发现什么样的新技术，以及到那个时候 agent 的参与会让竞赛生态演化成什么样子。
