需要先做一个时间校准：这篇文章发表到今天，已经过去超过十三个月了。在 AI 这个领域，十三个月是非常长的时间，可以发生翻天覆地的变化。所以我们听这篇文章的时候，要带着一点历史视角。

那二〇二五年七月是一个什么样的时间节点？那正好是 o 三、o 三 pro、o 四 mini 和 GPT 四点一这几个模型刚刚发布不久的阶段。这里解释一下：o 三是 OpenAI 推出的一款重点强化推理能力的语言模型，GPT 四点一则是在指令遵循和代码能力上做了大幅改进的模型。那时候，OpenAI 的 Agent SDK 也是刚刚推出早期版本，整个行业还在争论"AI agent 到底能不能在真实的生产环境里稳定可靠地运行"这个问题。Agent 就是能够自主执行多步骤任务的 AI 系统，不只是回答问题，而是能主动行动、调用工具、完成目标。那时候的 agent 就好比电动车行业里特斯拉 Model S 刚出来的阶段——技术已经跑通了，先行者看到了巨大的潜力，但大多数公司还在观望，还在问"它真的够可靠吗"。

带着这个背景，我们来看这篇文章。受访者叫 Chaz Englander，是 Model ML 的 CEO 和联合创始人。Model ML 是一家专门面向金融服务机构的 AI 基础设施公司，帮助金融机构用 AI 改造他们的工作流程。

为什么值得花二十多分钟专门聊这篇文章？我觉得有两个原因。第一，金融行业是 AI 落地难度最高的行业之一——合规要求极其严格、数据极度敏感、决策失误的代价极高——能在这里真正跑通的方案，背后的工程和产品思路，对所有行业都有很强的参考意义。第二，Chaz 在文章里谈到了 AI 原生公司的组织架构和工程哲学，这些判断我认为是非常有洞见的，不管你在什么行业，都值得认真思考。

我们先来了解这家公司的来历。

Chaz 说，他和他的兄弟 Arnie——也就是他的联合创始人——在卖掉了上一家公司之后，开始自己做投资。但他们发现自己并不擅长投资本身，反倒对"能不能用 AI 把投资流程自动化"这件事着了迷。时间大概是在 GPT 三点五刚刚推出、function calling 这个功能刚刚出来的时候。Function calling 就是让语言模型能够调用外部工具和 API 的能力，你可以把它理解成让 AI 从"只会说话"变成"能干活"的关键一步，这是后来所有 AI agent 的技术基础。

他们当时只是一个六人的家族办公室——家族办公室是一种专门管理高净值家族财富的小型机构——但他们说，用了这些语言模型之后，感觉自己有了相当于六十人团队的战斗力。原来六个人，用了 AI 之后战斗力变成了六十人，整整十倍的杠杆。

他们最初只是给自己做了一个原型系统，完全没有打算商业化。但随着自己用，越来越感受到这套系统在研究工作流上带来的效率提升和洞察质量的改善，就觉得：这不只是我们自己能用，金融行业里的其他机构应该都有同样的需求。Model ML 就是这样诞生的。

好，你可能会问，金融行业做 AI 有什么特别难的地方？这里我们需要多说几句背景，才能理解这家公司真正在解决什么样的硬问题。

金融机构和其他行业的公司有几个本质性的不同。第一是准确性要求极高，金融数据出一个错，可能直接影响到投资决策，进而影响到客户资产，容错率近乎为零。第二是合规性，金融机构受到极其严格的监管，数据怎么存、怎么处理、模型怎么工作、工作流是否可审计，这些都有法规要求，在很多市场 AI 系统的可解释性本身就是合规要求。第三是工作流适配性，金融机构内部的系统和流程往往是几十年积累下来的，极其复杂，你带进来的新工具必须能无缝嵌入这些已有的工作流，而不是要求员工完全改变做事的方式。

Chaz 说，正是因为这三点，通用目的的 AI 工具在金融场景里往往是"够不着"的。你直接去用 ChatGPT 分析一个投资组合，当然能得到一些有用的回答，但它不知道你们公司的内部数据在哪里，不知道 FactSet 和 Capital IQ 的数据库是怎么组织的，不知道你们历史上的投资决策记录，也不知道你们内部的合规约束。

所以 Model ML 从第一天起就是专门为金融服务行业构建的，这个"专门"体现在两个层次上，这是我要拆解的第一个核心点。

第一个层次叫做 agent 层。他们构建并调优了专门用于解析和处理金融专业数据的 agent 系统。这些数据包括结构化数据和非结构化数据，涵盖了金融机构最常用的 SharePoint 文件系统、Capital IQ、FactSet、Crunchbase 这些专业金融数据平台。

这几个数据库需要解释一下：FactSet 和 Capital IQ 是金融机构里最核心的两个数据平台，里面有公司财务数据、市场行情、分析师报告、私募股权数据等等，几乎是投资机构的数字命脉。Crunchbase 则主要涵盖初创公司和风险投资数据。这些数据库的数据量非常惊人——Chaz 说他们处理的数据可以达到几百张数据表、二十 TB。

让我帮你感受一下这个数字：二十 TB 是什么概念？如果你把一部标准高清电影的大小算作大概一点五个 GB，二十 TB 大概够存一万三千部电影，相当于普通手机存储容量的一万倍以上。在这个规模的数据集上构建 agent 并保证检索的准确率，在一年多前是极其困难的事情——语言模型的上下文窗口太小，根本塞不下这么多数据；检索如果不准，给出来的分析结论就是垃圾进垃圾出。

他们的 agent 不只是能回答问题，而是具备深度的上下文感知能力，能理解数据库的 schema——就是数据库的结构和字段定义——能编写查询代码，能在海量复杂数据中精准检索出需要的信息。这背后是大量针对金融场景的工程调优工作，不是拿一个通用模型直接上去就能做到的。

第二个层次叫做应用层，这是用户实际与 agent 交互的界面，专门为金融场景设计。它给金融机构提供了工具，让他们能构建自动化端到端工作流的 agent，支持以前根本不可能完成的分析任务。Chaz 说他们目前已经积累了数千个使用场景，而且每天都在涌现新的场景，很多场景是客户注册之后就能开箱即用的。

你可以这样来理解这两层架构：agent 层就像是一个经验丰富的金融分析师，懂数据、会编程、精通金融业务逻辑；应用层就是这个分析师的工作台，上面摆着他需要的所有专业工具，而且这个工作台是专门按照金融机构的具体工作方式定制的，不是一个什么都能用但什么都不专的通用工具。

好，第二个核心点：这套系统在实际工作中是怎样改变金融机构日常运作的？

Chaz 举了一个非常具体的例子：季度财报摘要。金融机构通常要追踪大量公司的财务表现，每个季度都要整理这些公司的财报摘要——拉财务数据、分析关键指标、做成幻灯片、上传到内部系统。以前，仅仅这一个任务，处理一家公司就可能需要好几个小时，而如果你的投资组合里有几十甚至上百家公司，这是一个非常沉重的重复性负担。

现在，整个流程全部由 agent 自动完成：agent 拉数据、格式化幻灯片、把 PowerPoint 发布到 SharePoint，全程不需要任何人工介入。

Chaz 说了一句话让我印象非常深刻：他说，他认为今年最大的转变就是，你早上来上班，你的工作已经在那等着你了。

我个人认为这句话描述的不只是一个效率提升，而是一种工作模式的根本性转变。以前我们说 AI 能帮你更快地做一件事；现在 Chaz 说的是 AI 会在你不在的时候、在你睡觉的时候、在你还没坐到位子上的时候，已经把事情做完了——你来了是来看结果、做判断、做决策的，不是来执行的。这是两种本质不同的人机关系。

这带来了一个更深层的问题：如果 AI 把执行层的工作都接管了，人的价值在哪里？

Chaz 的观察和很多人的直觉相反。他说，他们看到金融机构里的人变得更有价值了，而不是更没价值。为什么？因为自动化把那些重复性的基础执行工作接过去之后，人能够把全部的精力和注意力放在关系维护和战略判断上。以前一个分析师可能百分之六七十的时间都在整理数据、做格式化报告，这些时间现在解放出来了，他可以花更多时间跟客户深聊，花更多时间做高质量的战略分析，花更多时间发展对市场的深度洞察——这些才是真正难以被机器替代的东西。

他说，那些真正能赢的公司，是那些敢于把整个组织架构重新想一遍、从 AI 原生的视角来重构运营模式的公司。这极其困难，不是换一个工具那么简单，而是涉及到人的角色定义、工作流的重新设计、团队结构的调整。正是因此，Model ML 发现自己在早期很多时候是在扮演顾问的角色，帮助客户想清楚 AI 在哪些地方今天就能落地创造价值，同时也帮他们做十二个月后的路线图规划。

接下来讲第三个核心点：模型进步是怎样直接影响到他们产品能力的？

Chaz 说，每一次新模型发布，他们都能观察到明显的阶跃式能力进步，然后立刻把这些进步转化成对客户的价值交付。他点名提到了 o 三 pro、o 三、o 四 mini、GPT 四点一这几个模型。这些模型在推理能力、多模态能力——就是同时处理文字、图片、表格等不同形式信息的能力——以及指令遵循精度和工具集成能力上都有显著提升。

他说，推理能力和编程能力的进步，把他们产品的某些部分"送上了平流层"。这个比喻非常到位。平流层在飞行领域意味着什么？意味着几乎没有气流干扰、飞行极其平稳、速度极快。他用这个比喻说的是：之前勉强能做、但经常出错或需要人工兜底的事情，现在变得既稳定又快速，到了一个全新的量级。

更大的上下文窗口加上更强的推理能力，让他们可以解锁真正意义上的端到端工作流。用户现在可以把数据采集、数据分析、报告生成这些步骤链接在一起，完全自动地产出格式化的最终输出。之前你可能只能让 AI 做某个单独的步骤，比如分析一段财报文字，但整理成幻灯片这个步骤还是得人工做。现在整条链都可以全自动跑起来。

这对金融机构意味着什么？意味着以前需要团队花好几天做的大型分析报告，现在可能几个小时内就能出炉。意味着以前因为太费人力而根本做不到的分析场景，现在变得可行了。

第四个核心点：未来的 agent 世界会是什么样子？

Chaz 描述了一个更宏大的愿景。他说，最深刻的转变将是端到端工作流自动化的全面兴起，你的系统将充当控制塔，统领一支数字工人大军。随着这些 agent 在你整个数字世界中承担越来越复杂的多步骤任务，甚至连用户界面和我们与硬件的交互方式都会开始发生变化。

他说的"控制塔"这个比喻非常精准。你可以想象机场的控制塔：它不飞任何一架飞机，但它知道所有飞机的位置、状态、计划，它统筹协调，确保整个系统顺畅运行。未来的人类在这个工作流体系里，可能就是控制塔的角色，不再是飞行员。

他描述的 agent 未来是这样的：这些 agent 能够执行复杂的多步骤工作流，从 CRM 系统——就是客户关系管理系统——邮件、文件、外部数据供应商、会议录音和记录等各个来源采集、分析和呈现数据。而且这些 agent 不会只是等待指令，它们会预判需要做什么——不管是周期性的任务，比如每天、每周、每月、每季度、每年要完成的工作，还是由现实世界的事件触发的任务，比如一封重要邮件来了、一个会议结束了，agent 就会自动启动相应的工作流。

他说，这些工作流的输出可以是非常实质性的，比如一份完全由机器生成的一百页 PowerPoint，更快、更一致，而且二十四小时七天全天候可用。

这个愿景在一年多前听来还比较前瞻，但从今天来看，已经有越来越多的公司在往这个方向走。我个人认为，这篇文章里关于 agent 作为"后台自主执行系统"而非"前台问答工具"的定位，是最值得我们每个人认真思考的核心判断之一。

第五个核心点，也是这篇文章里我认为最有工程价值的部分：AI 原生的公司架构和工程哲学。

Chaz 说，他相信 AI 原生公司从结构上看会非常不同：更少的管理层级、更快的迭代周期、更紧密的反馈环。Model ML 自己就在践行这一点，他们采用完全扁平的组织结构。Chaz 和 Arnie 两个人，各自直接管理两位数——就是十几个——直属员工。

你可能会觉得这听起来不可思议。一个人管十几个直属下属，单是每人每周一次一对一会议，时间加起来就已经塞满了日历，精力从哪里来？Chaz 的答案是：AI 让这变得可管理了。所有的一对一沟通都是 AI 辅助的，笔记、待办事项、上下文、上次讨论了什么、这次要跟进什么，全部由 AI 自动整理和追踪，让他们能用更少的时间完成更高质量的沟通，同时保持对产品的紧密掌控。他说，这就是现代公司的运营方式：更像控制塔，而不是各自为政的层级式科层组织。

然后是工程哲学的部分，这是我个人最喜欢的一段。

Chaz 说了一句话：能够保持灵活性的关键，也许是创始人心态和工程组织里最核心的素质之一，就是"不要对你的代码有感情"。

他们以前什么都自己做：agent 抽象层、服务连接器，全部自己写。但后来他们调整了这个做法。如果 OpenAI 或者开源社区发布了更好的替代品——比如 OpenAI 的 Agent SDK，或者 MCP 连接器——他们就直接接进来，把自己原来写的代码删掉。

这里解释一下几个名词。OpenAI 的 Agent SDK 是 OpenAI 提供的一个开发框架，让开发者更容易构建和管理 AI agent，包括处理 agent 的运行循环、工具调用、并发执行等复杂问题。MCP 的全称是 Model Context Protocol，是一个开放协议，让语言模型能够以标准化的方式接入各种外部工具和数据源。Model ML 现在用这套工具来处理 agent 的运行循环、工具调用、安全护栏和系统集成，结果是：维护成本降低了，创新速度反而提升了。

这背后的逻辑是什么？Chaz 说得非常直接：他们不是要靠维护基础设施赢，他们要赢是靠交付客户价值。在 AI 这个基础设施快速进化的时代，如果你把大量工程精力花在维护自己写的基础设施层上，那你就是在做一件注定会被淘汰的事——因为大公司和开源社区会把这一层越做越好，你自己维护的那套很快就会变成技术债。聪明的做法是，把你所有的差异化精力放在你对这个行业的深度理解和对客户问题的解决上，基础设施能用现成的就用，能外包就外包。

这个哲学不只适用于 AI 创业公司，对任何在自己的产品里集成 AI 能力的工程团队都有参考价值。在快速进化的生态里，执着于自建每一层，往往是一种精力的错误分配。

好，说完了文章的核心内容，我们来聊聊这些东西对你的实际工作有什么参考价值。

首先，如果你是一个正在考虑在自己的工作场景里引入 AI 工作流的工程师或产品经理，Model ML 的故事给了一个非常好的切入方法：从最具体、最高频、最重复性的工作流入手。他们选择季度财报摘要，因为这件事有几个特点：规律可预测、格式化程度高、非常耗时，而且成功与否有清晰的判断标准。你在自己的工作里也可以找类似的任务——有没有每周都要做的报告？有没有每次都要从多个来源汇总信息的工作？有没有格式固定但内容每次都要更新的文档？这些地方往往是自动化价值最高的切入点，而且容易衡量效果、容易给利益相关方看到成果。

其次，如果你是在做 AI 产品开发或者 agent 系统设计的工程师，Chaz 说的"不要对你的代码有感情"这一点非常值得认真对待。我们都有自己花了大量时间写出来、维护了很久的代码，删掉它会让人不舒服，这是人之常情。但在 AI 基础设施这一层，整个生态系统的进化速度极快，六个月前你不得不自己写的东西，今天可能已经有了成熟的替代品。定期审视你的技术栈，问自己：这一层我们还有必要自己维护吗？特别是在 agent 架构这块，如果你还在手写 agent 循环、工具调用这些底层机制，值得认真评估一下是否有必要，把这些维护成本转化成产品迭代速度。

第三，关于金融行业或者其他高度专业化的垂直领域，这篇文章里一个很重要的启示是：通用 AI 工具在这些场景里的核心局限，往往不是模型能力本身，而是数据接入。Model ML 能在金融行业跑通，很大程度上是因为他们在数据接入层做了大量专门的工程工作——让 agent 能够连接和查询 FactSet、Capital IQ 这些金融专属数据库，能处理金融行业特有的非结构化文档，能在海量数据里保证检索精度。如果你在其他行业想做类似的 AI 工作流自动化，你首先要想清楚的关键问题是：你的行业里有哪些专有数据源？这些数据怎么接入？数据质量如何？这一层的工程工作，往往是整个系统能不能真正跑起来的根本。

说到组织架构，Chaz 描述的扁平化 AI 原生结构对今天很多团队来说是一个有意义的参照。但我个人认为，完全复制这套架构需要谨慎，因为它依赖的前提是团队成员的自主性非常强、对 AI 工具的使用非常熟练。如果你的团队还在 AI 工具的学习曲线上，过于激进的扁平化可能会带来管理混乱，而不是效率提升。这套做法适合已经建立了 AI 辅助工作习惯的团队去逐步推进，而不是一步到位的组织重构。

还有两个坑我想专门提醒一下。

第一个坑是过度承诺，或者叫"演示跑通就以为大功告成"。Chaz 说季度财报摘要现在全自动了，听起来很美，但这是他们在特定的数据环境、特定的模型选型、经过大量提示词调优和错误处理工程之后达到的结果。提示词就是给 AI 的指令和上下文，调优的过程往往需要很多次迭代才能稳定。如果你在公司里推进类似的自动化，需要给自己和利益相关方设置合理的预期：数据接入需要时间，提示词需要反复调整，各种边界情况需要处理，用户培训需要投入。自动化的第一个版本往往是脆弱的，需要多次迭代才能真正稳定可用。

第二个坑是忽略组织的人这一面。Chaz 非常强调，自动化的目的不是减少人，而是让人能够专注在更高价值的工作上。如果你在推进 AI 工作流的时候，没有提前想清楚你的团队在自动化之后"更高价值的工作"具体是什么，怎么帮助他们完成这个转型，那自动化的引入可能带来的是人心惶惶和抵触情绪，而不是生产力的提升。这是很多 AI 转型项目失败的真正原因，不是技术层面的问题，而是变革管理层面的问题。技术跑通只是一半，让人愿意用、能够用才是另一半。

好，最后来收个尾。

Model ML 的故事，本质上是一个关于"专门化"的故事。在通用 AI 能力越来越强的今天，真正的竞争优势不在于你用了什么模型，而在于你对某个垂直领域有多深的理解，你能不能把这种深度理解转化成 AI 系统真正能用、真正可靠、真正符合行业规范的解决方案。这适用于金融，也适用于医疗、法律、工业制造，以及所有专业知识密集的领域。

Chaz 在二〇二五年七月的很多判断，今天来看已经得到了相当程度的验证：端到端工作流自动化确实在快速普及，agent 作为后台自主执行系统的模式正在被越来越多的团队采用，AI 辅助的管理和协作也在越来越多的公司里出现。这意味着如果你现在去落地这些方案，条件只会比一年前更成熟，不会更差。

而他说的那句"不要对你的代码有感情"，我觉得是这篇文章里最值得反复咀嚼的一句话——不只是在工程层面，在产品策略和组织管理层面同样适用：不要对你现有的做法有感情，当更好的方式出现了，就切换过去，把精力留给真正创造差异化价值的事情。
