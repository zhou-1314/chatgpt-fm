那纳维-斯托克斯方程到底是什么？你不需要是数学家也能理解它的精髓，我来给你讲一个直观的版本。

想象你在浴缸里搅动水。水是流动的，浴缸里每一个位置的水，它的速度、流向、压力，都在随着时间不断变化。纳维-斯托克斯方程，就是用来描述这种流动的一组数学方程。它的核心是牛顿第二定律，也就是"力等于质量乘以加速度"，把这个定律推广到流体的每一个无穷小的体积元上，就得到了纳维-斯托克斯方程。

这套方程由两位十九世纪的科学家分别提出并完善：法国工程师克劳德-路易·纳维，和英国物理学家乔治·加布里埃尔·斯托克斯。它的应用范围极其广泛。设计飞机时，工程师用它来计算机翼周围的气流形态；气象学家用它来模拟大气运动，给我们预报明天的天气；医学里研究血液在血管和心脏中的流动，也离不开它。可以说，现代工程和科学里，凡是涉及到流体运动的地方，纳维-斯托克斯方程就在背后支撑着。

但这套方程有一个根本性的悬案，困扰了数学界将近九十年：如果我们给定一个非常光滑、规则的流体初始状态，随着时间推移，这个流体的运动会不会在某个有限的时间内"爆炸"？

这个"爆炸"有一个精确的数学定义，叫做"奇点"，英文是 Singularity。具体来说，就是某个点或某个区域的流体速度，在一段有限的时间内增长到无穷大。如果奇点出现了，就意味着这套把流体视为连续介质的方程在那一刻失效了。就好像你的地图在某一块区域突然出现了一个无限深的洞，地图本身就不再适用了，你必须换另一套更精细的工具来描述那里发生的事情——比如回到分子层面，逐个追踪每个粒子的运动。

为什么这个问题这么难？关键在于一个叫做"粘性"的量，英文是 Viscosity。粘性是流体内部的"摩擦力"，它的作用是耗散能量、抹平运动、让流体趋于平滑。水有粘性，蜂蜜的粘性远比水大，空气的粘性很小但也有。物理直觉告诉我们，有粘性存在，流体的运动应该会越来越平稳，极端的速度应该被"摩擦掉"，奇点不应该出现。正是因为这个直觉，很多数学家长期以来倾向于认为纳维-斯托克斯方程的解永远是光滑的，也就是奇点不会出现。

一九三四年，法国数学家让·勒雷证明了纳维-斯托克斯方程在一种"广义弱解"的意义上总是存在的，但他没能回答"这个解是否永远保持光滑"这个更深层的问题。从那以后，将近九十年，全球最顶尖的数学家都曾尝试回答这个问题，没有人成功。二〇〇〇年，克莱数学研究所把它列为七大千年难题之一。

现在我们知道答案了。答案是：不，光滑性不能保证，奇点会出现。

OpenAI 的 AI 系统给出的证明，证明了一个初始静止、运动非常光滑的流体，在施加一个光滑的外力之后，可以在有限时间内发展出奇点，某个位置的速度会增长到无界。更关键的是，在整个过程中，流体的能量始终是有限的，这满足了物理定律的约束。这在技术上对应的是克莱研究所原始问题陈述里的"C 项"和"D 项"，这是问题的两个等价变体，都被这个证明所解决。

那这个奇点长什么样？文章里有一个非常形象的描述，我把它翻译给你听：解是一个涡旋，一团旋转的流体，它向内螺旋收缩，同时在纵向越来越细长，就像一根意大利面条被拉伸一样。这个中心区域越来越细、速度越来越快，但整个过程中能量保持有限。

你可能会想：那技术难点在哪里？如果我想让流体速度无限大，直接在某个点施加一个无限大的力不就行了？问题就在这里——证明的要求是，这个奇点必须完全由流体自身的运动机制产生，而不是靠外部输入一个无限大的力。施加的外力始终必须是光滑的、有界的。这意味着方程里描述流体运动的各项，包括加速度、压力梯度、动量传递、粘性扩散，必须同时变得非常大，同时又以一种极其精确的方式相互抵消，使得外力始终保持光滑，而流体速度却在无界增长。用文章里的原话说，这些项必须同时"变大"又"精确地相互抵消"。这个精确的抵消机制，就是这个证明在数学上最艰难的核心所在。

解决纳维-斯托克斯问题的那个小组，同时运行了大约一万个并发 agent。一万个，你没有听错，同时在线、协同工作的 AI 智能体有一万个。整个攻坚过程，这些 agent 发送了二百七十万条消息，使用了大约一千三百亿个输出 token。如果放大到整个项目来看，所有千年大奖问题加在一起，总共发送了四百九十万条消息，使用了约三千亿个输出 token。这个规模本身就很说明问题——这不是一个 AI 在独自思考，而是成千上万个 AI 实例在并行探索一个巨大的解空间。

他们还用了一个很有意思的策略，文章里叫做 cross-pollination，直译是"交叉授粉"，借用的是植物学的术语。做法是：用 Codex，也就是 OpenAI 的代码和文本处理工具，从各个 agent 小组的中间结果里提炼出最有价值的洞见，然后把这些综合后的洞见重新作为 prompt 输入给其他小组，引导它们往更有希望的方向继续探索。最终找到纳维-斯托克斯解法的那个小组，正是通过这种交叉授粉的方式被引导的。

值得单独解释一下 Lean 是什么。Lean 是一种计算机辅助的形式化证明系统，也是一种编程语言。数学证明在传统上由人类数学家进行同行评审，这个过程既耗时又难免有疏漏——数学史上不乏被认可多年后才发现漏洞的证明。Lean 提供了另一条路：把证明的每一步推理转化成机器可以逐步核验的形式化语言。当 Lean 编译通过时，它代表着证明的逻辑结构是机器验证过的，没有跳步，没有隐含假设，每一步都是明确的。

对于我们写代码的人来说，这有一个非常贴切的类比：Lean 形式化就像是数学世界里的强类型系统加上穷举测试。你的程序写完，类型检查通过、测试通过，这当然不代表逻辑一定没问题，但它显著提高了正确性的置信度。Lean 对数学证明做的就是类似的事情：它把"这个证明对不对"的问题，变成了一个机器可以自动检验的问题。OpenAI 这次不仅给出了证明，还给出了 Lean 的形式化版本，这才是真正意义上的数学证明，而不是一个听起来很像证明的长篇论述。

欧拉方程是纳维-斯托克斯方程在粘性为零时的极限情形。你可以这样理解：如果你把纳维-斯托克斯方程里代表内部摩擦的粘性项去掉，剩下的就是欧拉方程。这个方程描述的是理想流体——没有粘性、没有内部摩擦的流体。这也是一道非常重要的开放数学问题。

有意思的是，OpenAI 的 agent 在正式开始攻坚纳维-斯托克斯之前，先把欧拉方程正则性问题作为一道"热身题"给解决了。而且这个结果出乎了 OpenAI 研究人员的意料——他们没有预料到 agent 能解决欧拉问题。近一百个 agent 协同工作了约五十个小时，给出了欧拉方程正则性问题的否定答案。具体来说，是无外力版本下欧拉方程可以发展出奇点。这个结果给了他们充分的信心，于是他们把其他所有问题的资源全部转移到了纳维-斯托克斯上来，集中力量打攻坚战。

然后是 OpenAI 与 Alpöge 和 Buckmaster 之间那段交流。九月六日，OpenAI 完成了 Lean 验证。此时他们以为这两个人手里有纳维-斯托克斯的解，于是主动联系对方，提出共同发布结果，并认可对方的优先权。但接触后才发现，Alpöge 和 Buckmaster 手里的是欧拉方程的"有外力"版本——和 OpenAI agent 解决的"无外力"版本是不同的数学变体。这两个变体在技术上有实质差异，给出的结论也不完全相同。

首先，最直接的启示是关于多智能体系统的架构设计。OpenAI 在这里展示的不是一个超强的单体模型在独自沉思，而是一万个 agent 在协同工作——分组探索不同的方向、组内实时通信、跨组交叉授粉、动态调配资源。这个架构背后有几个核心设计原则值得我们思考。

第一个原则是"方向多样性"。他们对纳维-斯托克斯问题的四个数学变体，A、B、C、D 分别部署了不同的 agent 组，无论最终答案是"奇点存在"还是"奇点不存在"，都有人在探索。这是在答案方向不确定时，覆盖解空间的聪明方式。对于我们来说，当你面对一个复杂的、没有确定解法的技术难题时，不要一开始就把所有资源押注在一个思路上，多路并行、保留多种可能性，往往能更快找到突破口。

第二个原则是"知识的交叉流动"。不同小组的中间发现会被汇总和提炼，再反哺给其他小组。这防止了各小组各自为战、重复劳动，也让有价值的中间洞见得以传播和放大。在一个大规模 agent 系统里，信息的流动方式和计算量同样重要。我个人觉得这个"交叉授粉"的机制对我们设计 agent 工作流有很强的参考价值——不要只想着让每个 agent 独立完成任务，要想怎么让它们的中间产出能够互相启发。

第三个原则是"动态资源再分配"。当欧拉问题被解决后，OpenAI 把原本分配给其他千年问题的 agent 全部转移到纳维-斯托克斯。这种动态的优先级调整，需要系统层面的协调能力，不是简单地启动一批 agent 让它们各跑各的就能做到的。这意味着你的 agent 系统需要有一个"调度层"，能够根据中间结果动态调整资源分配。

第四个原则是"模型的滚动升级"。在攻坚过程中，当更新版本的内部模型变得可用时，他们把 agent 切换到了新模型。这说明他们的 agent 框架对底层模型版本的切换是透明的，模型和上层逻辑有良好的解耦。这对我们构建 agent 系统是一个很好的工程实践参考：不要把某个具体的模型版本硬编码进你的业务逻辑，要让它可以方便地切换。

其次，Lean 形式化验证这件事对我们做 AI 辅助知识工作有重要的启示。AI 生成的推理链，不管看起来多么令人信服，都需要独立的核验机制。在数学里，Lean 扮演了这个角色。在软件工程里，类似的机制包括类型检查、单元测试、集成测试、形式化规约。

如果你在用 AI 来生成重要的业务逻辑、安全相关的代码，或者需要高置信度的分析结论，不要只靠人工读一遍来确认。你需要能够独立核验结论的机制——不一定是 Lean，但至少是可以和 AI 给出的过程相互独立地验证最终结论的手段。不要因为 AI 给出的推理过程看起来很有说服力，就跳过这一关。

第三，这件事对 AI 能力边界的认知是一个重大的更新信号。在这个结果出来之前，很多深度参与 AI 领域的人会认为，解决千年大奖级别的数学问题还需要很长时间，五年、十年，甚至更长。但现在我们看到它发生在八十八小时之内，由一个内部模型完成，而这个内部模型未来某一天会对外发布。

OpenAI 在文章里说了一句话，我认为值得反复思考："我们相信我们现在处于 AI 进步的下一个阶段。"这不是营销话术，它有实质的证据支撑。如果你的工作或者你的技术路线图，依赖于"AI 在某个复杂领域里还不行"这个假设，那这个假设可能需要以比你预期快得多的速度去更新了。

第四，从数学和科学本身的角度来看，纳维-斯托克斯奇点的存在性被证明，意味着这套用了几百年的流体力学模型在理论上有一个内在的局限性——在某些极端条件下，把流体视为连续介质的假设会失效。当然，这并不意味着我们明天就要放弃纳维-斯托克斯方程。就像量子力学的发现不会让牛顿力学在日常工程里失效一样，这个奇点在实际工程应用中也许永远不会真正出现，因为真实流体在分子尺度上是离散的，连续介质假设本来就有其适用范围。但它让我们在理论上对流体力学有了更完整的认识，填补了一个将近九十年的空白。

而且这个结果对湍流研究可能有更深远的影响。湍流是流体力学里另一个极其困难的问题，理查德·费曼曾经说它是经典物理最后一个真正未解之谜。奇点机制的发现，以及用来构造它的数学工具，可能会为理解湍流的数学结构打开新的思路。这是科学影响的涟漪效应，可能要在未来若干年里慢慢显现。

最后，我想说几点要避免的认知陷阱。

第一，不要把这个结果简单理解为"AI 比人类更聪明了"。这是一个特定规模、特定工程设计的系统，在一个特定类型的任务上取得的突破。一万个并发 agent、数千亿 token 的计算量、专门设计的协调和交叉授粉机制——这是一个工程壮举，也是一个关于"在特定条件下 AI 能做什么"的数据点。它告诉我们能力边界在哪里，但不代表所有问题都可以这样解决。

第二，不要低估形式化验证的重要性。OpenAI 得到的不仅仅是一个 AI 说"我觉得证明是这样的"，而是一个 Lean 编译通过的形式化证明。这个差别是实质性的。在数学上，没有经过严格验证的"证明"不叫证明，叫猜想。OpenAI 这里做到的是真正意义上的数学证明，这才是真正值得震撼的地方。

第三，文章末尾有一句很重要但容易被一笔带过的话，我想把它完整地念给你听：OpenAI 说，"这是一个里程碑，但它不是顶点，而是时间进程中的一个快照。" 接下来，这种能力会以怎样的方式演变、扩散到哪些领域，我们谁也说不准。但有一件事是确定的：今天的基准线，已经和一年前不一样了。

好，今天这期节目，我们聊了 OpenAI 用内部多智能体 AI 系统解决纳维-斯托克斯千年大奖问题这件大事。这是数学界的一个历史性时刻，也是 AI 能力边界的一次重大更新。八十八小时、一万个并发 agent、二百七十万条消息、一千三百亿个 token，这是一个关于规模、协作和持续迭代的故事，也是一个提醒我们重新校准预期的信号。

我个人认为，这件事最重要的意义，不在于那一百万美元的奖金，OpenAI 自己也说了不打算去申领，也不仅仅在于纳维-斯托克斯这道题本身，而在于它证明了一件事：有了足够强的基础模型和足够好的多智能体架构，AI 可以在人类最艰深的智识领域留下实质的印记。下一道被解开的问题是什么？我们不知道。但我们知道，解决它的速度，可能比我们所有人的预期都要快。
